### Install and preview

You need Node.js **22.18 or later in the 22.x series, or 24+**, pnpm, and a modern browser such as Chrome or Edge. Run these commands from this project folder:

```powershell
pnpm install
pnpm dev
```

Open the documents separately, or use the links in the preview toolbar:

- Resume: <http://127.0.0.1:5173/resume.html>
- Cover letter: <http://127.0.0.1:5173/cover-letter.html>

Use the actual address printed by Vite if port 5173 is busy. Saving JSON or Vue files refreshes the development preview. Press `Ctrl+C` in the terminal to stop the server.

### Format automatically on save

Open this project folder in VS Code. Its workspace settings use Prettier to format supported files when you save, including Vue, TypeScript, and JSON. On another computer, install the recommended **Prettier – Code formatter** extension if prompted, and run `pnpm install` first so the project's formatter version is available.

You can also format or check files from the terminal:

```powershell
pnpm format

```

Formatting adjusts layout without changing resume or cover-letter data. Generated `dist/` files, dependencies, the lockfile, and local environment files are excluded.

### Local profile and Git

Copy `src/data/profile.json` to `src/data/profile.development.json` and enter your personal information in that copy. Whenever the local file exists, both the development preview and production build use **the entire local file**. Values are never merged with `profile.json`; keep all required properties in the local copy. Missing or invalid properties cause an error. When the local file is absent, `profile.json` is used instead. Restart the development server after adding or removing the local file.

In the editing instructions below, “profile” means this selected file. Keep `profile.json` as a public template without private contact details.

`.gitignore` excludes the local profile, every JSON file in `src/data/applications/` except `sample-company.json`, environment files except `.env.example`, `node_modules/`, `dist/`, `.verification/`, logs, PDFs, and OS metadata. Add local exports or personal source documents to the ignore list if you save them elsewhere. Already tracked files remain tracked until removed from Git's index.

Commit `pnpm-lock.yaml`, `.env.example`, the profile template, the sample company, and the shared `.vscode` settings so another checkout can reproduce the project.

### JSON fields and empty values

Keep every field in the reusable profile, company information, cover letter, and complete items added to lists. A field being required means its **key must exist**; you can leave its value empty:

- Use `""` for text you do not want to display. Empty fields do not leave dangling separators or blank bullets.
- Use `[]` when a content list has no items. For example, `"projects": []` hides the Projects section.
- Keep each existing item's `id` nonempty and unique. Remove an item from its list instead of clearing its ID.
- Every application has `company`, `resume`, and `coverLetter`. Use `"resume": {}` when no resume changes are needed.
- Resume overrides are the exception: fields inside `resume`, partial `updates`, and collection operations can be omitted to inherit the reusable values. Empty ordering lists retain the existing/default order.

For example, contact links always have `id`, `label`, and `url`; use `"url": ""` when there is no link. Keep `phone` and `workAuthorization` in `personalInfo`, and `location` and `hiringManager` in `company`, even when their values are empty. The same rule applies to every field of a project, experience, education, certification, and language entry.

Each item in `certifications` must be an object with all five fields, rather than a string containing only the name. Leave unknown details empty:

```json
{
  "certifications": [
    {
      "id": "licensed-veterinary-nurse-japan",
      "name": "Licensed Veterinary Nurse (Japan)",
      "issuer": "",
      "date": "",
      "url": ""
    }
  ]
}
```

### Add and select an application

1. Copy `src/data/applications/sample-company.json` to a name such as `my-company.json` in the same folder.
2. Enter `company.name` and `company.position`. Keep `company.location` and `company.hiringManager`; use `""` when unknown or not needed.
3. Edit `coverLetter`. Add `resume` overrides only where this company needs different wording or ordering.
4. Copy `.env.example` to `.env.local`, then set:

```dotenv
VITE_APPLICATION=my-company
```

Use the filename **without `.json`**. The default is `sample-company` when no selection is set. Restart the development server after changing the selection. Build again whenever you want new production files; an existing export does not change when you edit JSON.

For a one-off selection in PowerShell, a shell environment variable takes precedence over the `.env` files:

```powershell
$env:VITE_APPLICATION = 'my-company'
pnpm build
Remove-Item Env:VITE_APPLICATION
```

The sample company and cover letter are a starting template. Replace their placeholders with the real application details. The sample includes an explicit date; update it for each application. Dates do not automatically change to today.

If the preview or build reports an error, check the named JSON field or application filename. The project checks required fields, value types, unknown field names, and calendar dates. A missing application selection lists the available filenames. JSON must use double quotes and cannot contain comments or trailing commas.

### How resume overrides work

`createResumeData(profile, application)` creates a separate document object without changing either input. Keep `"resume": {}` to use the reusable resume unchanged. Fields inside this override object are optional: omitted values inherit the profile, while an explicit `""` hides a text field.

- Omitted fields keep their profile values. A `personalInfo` patch changes only its named fields, so changing the title keeps the contact information.
- `summary` replaces the summary when supplied. An empty string hides the summary section.
- Collections (`skills`, `experience`, `projects`, `education`, `certifications`, `languages`) use stable `id` values. Keep existing IDs when editing entries.
- `updates` changes only named fields of an existing item. A supplied list within an item, such as `bullets`, `items`, or `details`, replaces that **whole list**. `[]` clears it.
- `remove` deletes named items; `add` accepts complete new items with new IDs. To clear a collection, remove all its IDs.
- `order` moves the listed IDs to the front in that order, then keeps the remaining items in their existing order.
- Collection operations run in this order: **remove → update → add → order**. Unknown IDs and duplicate IDs fail with an error instead of silently losing content.
- `sectionOrder` works the same way as ordering items: listed sections come first; unlisted sections follow. Empty sections are hidden.
- If supplied, `personalInfo.links` replaces the entire contact-link list. Leave it out to preserve all existing links.

For example, this application-specific `resume` block changes the title, replaces one job's bullets, and moves Skills before Experience. All other reusable data remains:

```json
{
  "personalInfo": {
    "professionalTitle": "Software Developer"
  },
  "experience": {
    "updates": [
      {
        "id": "dominosoft",
        "bullets": ["[Write the complete bullet list to use for this application.]"]
      }
    ]
  },
  "sectionOrder": ["summary", "skills", "experience"]
}
```

Put that object under the application's `resume` key. Look up IDs in `profile.json`; do not use array indexes. Valid section names are `summary`, `experience`, `skills`, `projects`, `education`, `certifications`, and `languages`.

### Edit projects

Each item in `profile.json`'s `projects` list uses this structure:

```json
{
  "id": "catfolio",
  "name": "Catfolio",
  "url": "https://catfolio.sumihana.workers.dev/dashboard",
  "repository": "https://github.com/createdbymonet/catfolio",
  "description": "Vue 3 and TypeScript web app for managing cat care, health events, medical records, memories, and multiple cat profiles."
}
```

All five keys are required. `url` is the live/demo site; `repository` is the source-code repository. The project name stays plain text, with compact **Live** and **Repository** links beside it when their URLs are available. Keep either field as `""` when there is no link:

```json
{
  "url": "",
  "repository": ""
}
```

These two fields belong inside the complete project object above. Empty values produce no anchors or placeholders; when both are empty, no link area appears. An empty `description` leaves no trailing separator. Set `"projects": []` in `profile.json` to hide the entire Projects section. In an application-specific `updates` patch, specify only the fields you want to change; omitted links keep their profile values.

### Edit the cover letter

Keep all eight fields in the application's `coverLetter`. Use ordinary text, not HTML. `body` is a list with one string per paragraph. For example:

```json
{
  "date": "",
  "recipient": "Hiring Manager",
  "greeting": "Dear Hiring Manager,",
  "opening": "",
  "body": [],
  "closing": "",
  "signOff": "Sincerely,"
}
```

Use an explicit `YYYY-MM-DD` date, or `""` to hide the date. Set any other text field to `""` to hide it, and use `"body": []` for no body paragraphs. There are no automatic recipient, greeting, or sign-off fallbacks: write the wording you want, or leave an empty string. An empty `recipient` stays hidden even if `company.hiringManager` is filled in.

Sender information always comes from the selected profile file. Resume overrides do not change the cover-letter sender. The company and position come from this application's `company` object. Set `company.location` to `""` to hide its line.

### Build and save PDFs

```powershell
pnpm build
```

This runs TypeScript checking and the data/rendering tests, builds both Vite entry points, then renders the Vue documents into standalone HTML with embedded CSS:

```text
dist/resume.html
dist/cover-letter.html
```

Double-click either generated file to open it directly in a browser. The files contain selectable text and do not need a server, Vue runtime, external fonts, or a companion assets folder. Keep both files together if you want their preview navigation links to work. Nothing is uploaded or published.

You can also use `pnpm preview` to serve the finished build; use the address it prints and append `/resume.html` or `/cover-letter.html`.

For **each** document:

1. Open the generated HTML and choose **Print**, or press `Ctrl+P`.
2. Select **Save as PDF**, paper **Letter (8.5 × 11 in)**, scale **100%**, and margins **Default** so the CSS page settings apply.
3. Turn off **Headers and footers**. Enable **Background graphics** to retain the brick-red header and skill backgrounds.
4. Check the entire print preview, then save as `resume.pdf` or `cover-letter.pdf`.

The preview toolbar, screen background, and shadow disappear in print. The design follows Template C's single-column layout, Arial typography, brick-red header, and compact spacing. Print CSS adds page-break protection and continuation-page spacing: the first page starts at the top, later pages have 10 mm top spacing, pages have 10 mm bottom spacing, and document content has 16 mm side padding. Content can flow onto additional pages; check pagination after editing instead of assuming it will always fit one page.

You can run checks separately:

```powershell
pnpm typecheck
pnpm test
```

### Quick workflow

1. Copy an existing application JSON.
2. Rename it for the target company.
3. Enter the company and position.
4. Add resume overrides only where needed.
5. Write or edit the cover letter.
6. Select the application in `.env.local`.
7. Run `pnpm dev`.
8. Review `/resume.html`.
9. Review `/cover-letter.html`.
10. Run `pnpm build`.
11. Open both generated HTML files in `dist/`.
12. Print each one → Save as PDF.

### JSON の必須項目と空の値

共通プロフィール、会社情報、カバーレター、一覧に追加する項目には、すべてのフィールドを残してください。「必須」は **キーを削除しない**という意味で、値は空にできます。

- 表示しない文字列には `""` を指定します。空の項目だけのために区切り記号や空の箇条書きが残ることはありません。
- 内容のない一覧には `[]` を指定します。たとえば `"projects": []` にすると、Projects セクション全体を非表示にできます。
- 既存の項目の `id` は空にせず、重複しない値を保ってください。項目が不要な場合は、ID を空にするのではなく一覧から項目を削除します。
- 応募先 JSON には `company`、`resume`、`coverLetter` を必ず含めます。履歴書を変更しない場合は `"resume": {}` にします。
- 例外は履歴書の上書きです。`resume` 内の項目、部分更新の `updates` 内のフィールド、一覧の操作は省略でき、省略した値は共通データを引き継ぎます。並び順の配列を空にした場合は、元の順序・既定の順序を保ちます。

たとえば、連絡先リンクには `id`、`label`、`url` を必ず含め、リンク先がない場合は `"url": ""` にします。`personalInfo` の `phone` と `workAuthorization`、`company` の `location` と `hiringManager` も、値が空でもキーは残してください。プロジェクト、職歴、学歴、資格、言語の各項目も同じルールです。

`certifications` の各項目は、資格名だけの文字列ではなく、5 つのキーを持つオブジェクトにします。発行元・取得日・URL が不明な場合は、空文字列のままで構いません。

```json
{
  "certifications": [
    {
      "id": "licensed-veterinary-nurse-japan",
      "name": "Licensed Veterinary Nurse (Japan)",
      "issuer": "",
      "date": "",
      "url": ""
    }
  ]
}
```

### 応募先を追加・選択する

1. `src/data/applications/sample-company.json` を、同じフォルダー内の `my-company.json` などの名前でコピーします。
2. `company.name` に会社名、`company.position` に応募職種を入力します。`company.location` と `company.hiringManager` も残し、不明・不要な場合は `""` にします。
3. `coverLetter` を編集します。会社ごとに変更が必要な箇所だけ、`resume` に上書き内容を追加します。
4. `.env.example` を `.env.local` にコピーし、次のように設定します。

```dotenv
VITE_APPLICATION=my-company
```

指定するのは、**`.json` を除いたファイル名**です。未指定の場合は `sample-company` が使われます。応募先を切り替えたら、開発サーバーを再起動してください。完成版の HTML を更新するには、その都度ビルドが必要です。JSON を保存しただけでは、すでに出力した HTML は変わりません。

一度だけ別の応募先でビルドする場合は、PowerShell で次のように指定できます。環境変数は `.env` ファイルより優先されます。

```powershell
$env:VITE_APPLICATION = 'my-company'
pnpm build
Remove-Item Env:VITE_APPLICATION
```

サンプルの会社情報とカバーレターは編集用のひな形です。実際の応募先に合わせて、未記入の項目を置き換えてください。サンプルには日付が指定されているので、応募のたびに更新してください。自動的に今日の日付にはなりません。

プレビューやビルドでエラーが出た場合は、メッセージに表示された JSON の項目名や応募先のファイル名を確認してください。必須項目、値の型、項目名の誤字、日付の妥当性をチェックしています。指定した応募先が見つからない場合は、選択できるファイル名が表示されます。JSON の文字列にはダブルクォーテーションを使い、コメントや末尾の余分なカンマは入れないでください。

### 履歴書の上書きルール

`createResumeData(profile, application)` は、共通データと応募先のデータから、表示用のデータを新しく作ります。元の JSON データは変更しません。共通の履歴書をそのまま使う場合は、`"resume": {}` を残してください。この上書きオブジェクト内の項目は省略でき、省略した値は共通データを引き継ぎます。文字列に `""` を明示すると、その項目を非表示にできます。

- 指定しなかった項目は選択されたプロフィールの値を使います。`personalInfo` も指定した項目だけが変わるため、肩書きだけを変えても連絡先は残ります。
- `summary` を指定すると自己紹介を置き換えます。空文字列にすると、そのセクションを非表示にできます。
- `skills`、`experience`、`projects`、`education`、`certifications`、`languages` の各項目は、固有の `id` で指定します。内容を編集するときも、既存の ID は変えないでください。
- `updates` は、既存の項目のうち指定したフィールドだけを変更します。ただし、`bullets`、`items`、`details` などの配列を指定した場合は、**その配列全体**を置き換えます。`[]` なら空になります。
- `remove` で指定した ID の項目を削除できます。`add` には、新しい ID を持つ項目の全内容を指定します。セクション内を空にしたいときは、すべての ID を `remove` に指定します。
- `order` に指定した ID を、その順序で先頭に並べます。指定しなかった項目は、元の順序を保って後ろに続きます。
- 処理の順序は **削除 → 更新 → 追加 → 並べ替え** です。存在しない ID や重複した ID はエラーになるため、気づかないうちに内容が消えることを防げます。
- `sectionOrder` も同じルールでセクションを並べ替えます。指定したものが先頭に、残りが後ろに続きます。内容が空のセクションは表示されません。
- `personalInfo.links` を指定した場合は、連絡先リンクの一覧全体を置き換えます。既存のリンクを残したい場合は、この項目を省略してください。

たとえば、次の内容を応募先 JSON の `resume` に入れると、肩書きと特定の職歴の箇条書きを変更し、スキルを職歴より前に表示できます。それ以外の共通データは引き継がれます。

```json
{
  "personalInfo": {
    "professionalTitle": "Software Developer"
  },
  "experience": {
    "updates": [
      {
        "id": "dominosoft",
        "bullets": ["[この応募先向けに使う箇条書きを、すべてここに指定します。]"]
      }
    ]
  },
  "sectionOrder": ["summary", "skills", "experience"]
}
```

ID は `profile.json` で確認してください。配列の何番目かではなく、ID で指定します。セクション名として使えるのは、`summary`、`experience`、`skills`、`projects`、`education`、`certifications`、`languages` です。

```json
}
```

5 つのキーはすべて必須です。`url` は公開サイト・デモの URL、`repository` はソースコードのリポジトリ URL です。プロジェクト名は通常の文字として表示し、その横に URL があるものだけ **Live**・**Repository** のリンクをコンパクトに表示します。リンク先がない場合もキーを残し、値を `""` にしてください。

```json
{
  "url": "",
  "repository": ""
}
```

この 2 項目は、上のプロジェクトオブジェクト内に指定します。空文字列の場合は、空のリンクや仮の表示を作りません。両方とも空なら、リンク欄自体を表示しません。`description` が空なら、説明の前の区切り記号も表示しません。Projects セクション全体を非表示にしたい場合は、`profile.json` で `"projects": []` にしてください。応募先ごとの `updates` では、変更する項目だけを指定できます。省略したリンクは共通データの値を引き継ぎます。

### カバーレターを編集する

応募先 JSON の `coverLetter` には、8 つのフィールドをすべて残します。HTML ではなく、普通の文章で入力してください。`body` は、1 つの文字列が 1 段落になる配列です。たとえば、次のように指定できます。

```json
{
  "date": "",
  "recipient": "Hiring Manager",
  "greeting": "Dear Hiring Manager,",
  "opening": "",
  "body": [],
  "closing": "",
  "signOff": "Sincerely,"
}
```

日付は `YYYY-MM-DD` 形式で入力し、表示しない場合は `""` にします。他の文字列も `""` にすると非表示になり、本文の段落がない場合は `"body": []` にします。宛名・挨拶・署名の結びは自動補完されません。表示したい文言を入力するか、空文字列にしてください。`company.hiringManager` に名前があっても、`recipient` が空なら宛名は表示しません。

差出人の氏名と連絡先は、常に選択されたプロフィールから取得します。履歴書用の上書き内容は、カバーレターの差出人には反映されません。会社名と職種は、その応募先の `company` から取得します。所在地の行を表示しない場合は、`company.location` を `""` にします。

### 完成版の HTML と PDF を作る

```powershell
pnpm build
```

TypeScript のチェックとデータ・表示のテストを実行し、Vite で 2 ページをビルドしてから、Vue の書類を単独で開ける HTML に変換します。CSS も HTML 内に含まれます。

```text
dist/resume.html
dist/cover-letter.html
```

出力したファイルは、ダブルクリックでブラウザーに開けます。文字は選択可能で、サーバー、Vue の実行環境、外部フォント、付属の assets フォルダーは不要です。プレビューのページ切り替えリンクを使う場合は、2 つの HTML を同じフォルダーに置いてください。アップロードや公開は行いません。

`pnpm preview` で完成版をローカル配信することもできます。表示されたアドレスに `/resume.html` または `/cover-letter.html` を付けて開きます。

**それぞれの書類で**、次の操作を行ってください。

1. 出力した HTML を開き、**Print** ボタンまたは `Ctrl+P` で印刷画面を開きます。
2. 送信先を **PDF に保存**、用紙を **Letter（8.5 × 11 インチ）**、倍率を **100%**、余白を **既定** にします。CSS のページ設定が適用されます。
3. **ヘッダーとフッター**をオフにし、**背景のグラフィック**をオンにします。赤いヘッダーやスキル欄の背景を残せます。
4. 全ページのプレビューを確認してから、`resume.pdf` または `cover-letter.pdf` として保存します。

画面用のツールバー、背景、影は印刷されません。書類のデザインは Template C の 1 カラム構成、Arial 系の書体、赤いヘッダー、コンパクトな余白を引き継いでいます。印刷用 CSS では、項目の途中での改ページを抑え、2 ページ目以降の余白も確保しています。1 ページ目は上端から始まり、2 ページ目以降は上に 10 mm、各ページの下に 10 mm、本文の左右に 16 mm の余白を設けています。文章量によっては複数ページになるため、編集後は必ず印刷プレビューを確認してください。

チェックだけを実行することもできます。

```powershell
pnpm typecheck
pnpm test
```

### 応募時の手順

1. 既存の応募先 JSON をコピーする。
2. 応募先の会社名に合わせてファイル名を変更する。
3. 会社名と応募職種を入力する。
4. 必要な箇所だけ履歴書の上書きを追加する。
5. カバーレターを書く・修正する。
6. `.env.local` で応募先を選ぶ。
7. `pnpm dev` を実行する。
8. `/resume.html` を確認する。
9. `/cover-letter.html` を確認する。
10. `pnpm build` を実行する。
11. `dist/` に出力された 2 つの HTML を開く。
12. それぞれ「印刷 → PDF に保存」で保存する。
