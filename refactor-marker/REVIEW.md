# Refactor Marker 0.2.0 変更・確認記録

記録日: 2026-10-21。既存の拡張機能を継続して修正し、バージョンは **0.2.0** のままとしています。現在の機能と使い方は [README](./README.md) を参照してください。

## 今回の整理

- 同じワークスペースフォルダーで **Create Group** に同じ完全パスを入力すると、色を選び直さず既存グループへ範囲を追加します。大文字・小文字は区別し、既存の ID と色を保持します。
- 保存済みの同名グループは、作成日時がすべて有効なら最古、欠落を含む場合は保存順で最初のグループの ID・色を保持して整理します。範囲は元の出現順でまとめ、同じファイルと座標が完全一致するものだけを除去します。不一致の重なりは勝手に削除せず停止します。
- 欠落した作成・更新日時だけを既存の日時、範囲の追加日時、固定の基準日時から補完します。不正な日時文字列や `null` は拒否します。補完だけの場合も保存成功後に公開し、失敗時は元のメタデータを維持して該当フォルダーの変更を止めます。既存名への名前変更は明示的に拒否します。
- サイドバー上部に **Add to Existing Group** を追加し、サイドバーと通常の選択一覧から内部 UUID を取り除きます。
- 日本語の README、変更履歴、確認記録へ統一しました。社内利用のためテストコードとテストランナーは削除し、追加のテストや確認用データは作成しません。

## Orange の表示原因と修正

従来のアイコンが使用した `charts.orange` は登録済みの VS Code 標準色であり、未登録の名前や誤字が原因ではありません。標準の通常テーマでは `#D18616` ですが、ハイコントラストのライトテーマでは `#0F4A85` の青色が指定されています。テーマによる上書きも可能で、エディターの固定の橙色背景とは異なる仕組みでした。[VS Code の色定義](https://github.com/microsoft/vscode/blob/main/src/vs/platform/theme/common/colors/chartsColors.ts)

VS Code 標準の色登録機構により拡張専用テーマ色 `refactorMarker.orangeIcon` を登録し、通常・ハイコントラストの明暗テーマすべてに橙系の初期値を指定します。丸い標準アイコンとテーマ色の組み合わせを維持し、他 6 色と約 30% の背景色は変えません。[テーマ色の登録仕様](https://code.visualstudio.com/api/references/contribution-points#contributes.colors)

色の設定が正しくても、実際のテーマでの視認性は手動確認が必要です。確認手順と期待結果は README の「制限と動作確認」に記載しています。

## 以前のレビューで修正した重要事項

| 項目 | 修正内容 |
| --- | --- |
| 保存先の別名参照 | キャッシュ・メタデータ・ソースのリンクやジャンクションを拒否し、元のソースへの誤書き込みや、生成ファイル・重複検査の回避を防止。 |
| 複数ルートの競合 | 同じ物理ルートの二重登録を拒否し、入れ子のルートをまたぐ範囲の重なりも検査。競合する復元データは上書きせず通知。 |
| 範囲の境界をまたぐ置換 | どちらか一方の境界をまたぐ空でない置換でも、影響した範囲だけを無効化。他ファイルや同じグループの別範囲を保持。 |
| 追従中のエクスポート | 待ち行列を待って最新座標を読み、出力先の置き換え直前にもソースとメタデータを再確認。古い内容の出力を中止し、一時ファイルを片付ける。 |
| 複数行文字列の内容 | 各範囲の先頭行だけに追加インデントを付け、2 行目以降のバイト列を保持。 |
| 選択先の識別 | グループの完全パス、ファイル・行番号、範囲数、色を表示。同じ表示名のワークスペースはフォルダーパスで識別。 |
| 無効なサイドバー範囲 | ファイル末尾などへ丸めて移動せず、エラーを通知。エディターを開いた後も範囲 ID から最新座標を再取得。 |

## 確認の扱い

現在の開発用コマンドは `npm run check`（コンパイルと lint）と `npm run package` です。以前のレビューでは単体確認 113 件と Windows / VS Code 1.142.0 のホスト確認 43 項目を通過しましたが、これはテスト機構を削除する前の履歴です。今回の変更が同じ確認を通過したという意味ではありません。古い配布物のハッシュや件数を、現在の成果物の証拠としては使用しません。

標準ダイアログ、サイドバー上部の追加ボタン、内部 UUID の非表示、Orange を含む 7 色の実際の見た目、再起動後の復元は手動で確認してください。README に操作と期待結果を記載し、未実施の操作を確認済みとは扱いません。最低対応の VS Code 1.95 や macOS/Linux を使う場合は、その環境でも確認が必要です。

## 維持する制限と注意

処理はローカルで完結し、実行時の外部 API、テレメトリ、AI 連携、ソースのアップロード、追加の実行時依存関係はありません。エクスポートは下書きであり、import・引数・戻り値・非同期処理・外部依存関係を分析せず、コンパイル可能性を保証しません。元のソースコードを変更・削除・置き換えません。

範囲の追従は位置に基づきます。拡張機能が無効な間の編集、ファイル移動、外部変更、未保存内容の消失では、範囲の作り直しが必要になることがあります。元に戻す操作は、削除済みのマーカー情報を復元しません。ハードリンクの同一性や、第三者による同時のファイル操作を完全に追跡する仕組みはありません。

複数ウィンドウや手動のメタデータ編集の競合を統合する仕組みはありません。全削除は全フォルダーを事前確認しますが、複数フォルダーをまたぐトランザクションではありません。異常時は通知と出力パネルを確認し、元のメタデータを保持して原因を修復してください。
