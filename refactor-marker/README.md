# Refactor Marker

Refactor Marker は、リファクタリング中のコードを整理する、ローカル動作の VS Code 拡張機能です。複数のファイルにある関連コードの範囲を名前と色でまとめ、階層構造を入れ子の関数の下書きとして出力できます。

バージョン **0.2.0** は、**社内利用向け**です。**VS Code 1.95 以降**が必要です。

## 使い方

1. ワークスペースフォルダー内に保存されたローカルファイルを開き、ひと続きのコード範囲を選択します。
2. コマンドパレットまたはエディターの右クリックメニューから **Refactor Marker: Create Group** を実行します。
3. `Order/Validation` などの名前を入力します。新しい名前なら色を選びます。同じワークスペースフォルダーに同じ完全パスのグループがある場合は、色を選び直さず、そのグループへ選択範囲を追加します。
4. 同じファイルや同じワークスペースフォルダー内の別ファイルでコードを選び、**既存グループに追加**（コマンド名: **Refactor Marker: Add to Existing Group**）を実行して追加先を選びます。サイドバー上部の同じボタン（リストと選択範囲のアイコン）からも追加できます。
5. アクティビティバーの **Refactor Marker** を開きます。グループ、ファイル、範囲を展開し、具体的な範囲をクリックするとそのコードへ移動します。実グループをクリックした場合は最初の範囲へ移動します。
6. グループの右クリックメニューやコマンドパレットから名前変更、色変更、削除、エクスポートを実行します。**Clear All Groups** では確認が表示されます。

1 つのグループに、複数ファイルの複数範囲を登録できます。範囲は**追加した順序**を保持し、同じファイルへ戻って追加しても並べ替えません。行全体をハイライトするため、同じグループ内であっても同じ行に別のマーカーを置けません。選択の終点が次の行の先頭の場合、その次の行は含まれません。

グループ名の一致は、入力全体の前後の空白を除いた**完全パス**で判定し、**大文字と小文字を区別**します。`Order/Validation` と `Order/Validation` は同じグループですが、`order/Validation` や `Other/Validation` は別のグループです。同名で追加しても、既存グループの色と内部 ID は変わりません。別のワークスペースフォルダーにある同名グループとは統合しません。

サイドバーにはグループ名、範囲数、ファイル、行番号を表示し、内部 UUID は表示しません。コマンドの選択一覧でも、完全なグループパスと最初に追加したファイル・行番号、範囲数、色で追加先を確認できます。複数ルートで表示名が同じ場合は、フォルダーのパスも表示します。

対応色は **青（Blue）、緑（Green）、黄（Yellow）、紫（Purple）、赤（Red）、オレンジ（Orange）、グレー（Gray）** です。7 色とも背景色の定義を集約し、不透明度を約 **30%** にしています。不透明度の設定 UI はありません。

Orange のアイコンには、通常とハイコントラストの明暗テーマ向けに専用の橙色を指定しています。テーマや色のカスタマイズによって見え方は変わるため、実際の表示は使用するテーマで確認してください。

## グループのパスと階層

`/` で階層を区切ります。

```text
Order
├── Validation
│   ├── src/order.ts
│   │   └── Lines 10–18
│   └── src/validator.ts
│       └── Lines 5–12
└── Calculation
    └── src/order.ts
        └── Lines 25–40
```

`Order`、`Order/Validation`、`Order/Calculation` という名前のグループでこの階層になります。`Order/Validation` だけが存在してもかまいません。その場合はサイドバーとエクスポートで仮想の親 `Order` を作ります。仮想の親にはグループの保存データがなく、エクスポートのみ可能です。名前変更、色変更、削除はできません。

名前には文字（日本語なども含む）、数字、半角スペース、ハイフン `-`、アンダースコア `_`、スラッシュ `/` を使用できます。`Order Processing`、`group_a`、`group-a`、`groupA/childA` は有効です。`@`、`#`、`.`、`\`、`:` などの記号は使えません。先頭・末尾の `/`、`//`、空白だけの階層は無効です。入力全体の前後の空白は除去しますが、その他の無効な入力を自動修正しません。作成と名前変更で同じ検証を行います。旧形式の名前はそのまま読み込めます。新しい規則に合わない旧グループをエクスポートする場合は、先に名前を変更してください。

名前変更は**選択した実グループだけ**に適用し、子の名前は変更しません。同じワークスペースフォルダーで既に使われている完全パスへの名前変更は拒否し、暗黙の統合は行いません。範囲を追加する場合は **Create Group** で同じ名前を指定するか、**Add to Existing Group** を使用してください。削除するのも**そのグループのメタデータ、範囲、ハイライトだけ**で、子グループは残ります。以前の親は仮想ノードになることがあります。編集によって最後の範囲が無効化されても、空のグループは残ります。

## 関数の下書きとして出力

**Refactor Marker: Export Group as Function** を実行して最上位の階層を選ぶか、実グループまたは仮想グループの右クリックメニューから実行します。**子から実行した場合も、そのワークスペースフォルダー内の最上位の階層全体を出力**します。

下書きの出力先は **`.vscode/cache/refactor-marker/`** です。ファイル名には最上位の階層だけを使用し、小文字化してスペースを `_` に置き換えます。既存の `_` と `-` は保持します。

| グループのパス | 下書きのファイル名 |
| --- | --- |
| `Order Processing` | `order_processing.ts` |
| `Order-Processing` | `order-processing.ts` |
| `Order_Processing` | `order_processing.ts` |
| `groupA/childA` | `groupa.ts` |

異なる最上位名が同じファイル名になる場合は、警告を表示して中止します。安全に出力できない旧形式の名前や予約ファイル名は、先に変更してください。既存の出力ファイルがある場合は VS Code 標準のダイアログで **Overwrite** または **Cancel** を選びます。キャンセルするとファイルは変わりません。出力先の下書きに未保存の編集がある場合は、保存または閉じてから再実行してください。

各階層の名前を PascalCase の関数名へ変換します。`groupA` は `GroupA`、`order_processing` は `OrderProcessing`、`api-request` は `ApiRequest` になります。各グループ自身の範囲を追加順に出力してから、子の関数を入れ子で出力します。子のコードを親の本体へ重複させません。仮想の親も関数になります。各範囲の前にワークスペース相対のファイルパスをコメントとして付け、同じファイルの範囲が続く場合も省略しません。

```ts
function Order() {
  // src/order.ts
  const order = createOrder(user);

  // src/api.ts
  await saveOrder(order);

  function Validation() {
    // src/validator.ts
    validateOrder(order);
  }
}
```

現在のソースドキュメント（エディターの未保存の内容も含む）から保存範囲のテキストをコピーします。追加のインデントは各範囲の先頭行だけに付け、2 行目以降のバイト列とインデントはそのまま保持します。これにより、複数行の文字列や行継続の内容を変えません。コードの整形や修正は行いません。ソースファイルが見つからない、範囲が無効、出力中の変更を検出した場合は、途中の下書きを保存せずエラーを表示します。エクスポートはグループのメタデータや元のソースコードを変更しません。拡張機能自身のキャッシュ内のファイルや旧メタデータはマーカーの対象にできません。

**生成した関数ファイルはリファクタリング用の下書きです。正しい TypeScript やコンパイル可能なコードであることは保証しません。エクスポート時に import、引数、戻り値、非同期処理、外部依存関係を分析しません。** import、引数、戻り値、`async` の自動生成は行わず、元のソースを置き換えたり削除したりしません。生成ファイルの先頭にも注意書きを付けます。

## コマンド

| コマンドパレットでの表示 | コマンド ID | 動作 |
| --- | --- | --- |
| Refactor Marker: Create Group | `refactorMarker.createGroup` | 新しい名前ならグループを作成し、同じ完全パスがあれば既存色のまま範囲を追加します。 |
| Refactor Marker: Add to Existing Group | `refactorMarker.addToExistingGroup` | 同じワークスペースフォルダーのグループへ選択範囲を追加します。 |
| Refactor Marker: Export Group as Function | `refactorMarker.exportGroupAsFunction` | 最上位の階層全体を 1 つの下書きに出力します。 |
| Refactor Marker: Rename Group | `refactorMarker.renameGroup` | 選択した保存済みグループだけの名前を変更します。 |
| Refactor Marker: Change Color | `refactorMarker.changeColor` | グループの全範囲の色を変更します。 |
| Refactor Marker: Delete Group | `refactorMarker.deleteGroup` | 選択したグループのメタデータと範囲だけを削除します。 |
| Refactor Marker: Clear All Groups | `refactorMarker.clearAll` | 確認後、ワークスペースの全グループを削除します。 |
| Refactor Marker: Reveal Group | `refactorMarker.revealGroup` | クリックした範囲、またはグループの最初の範囲へ移動します。 |

## 保存場所と移行

メタデータはスキーマ **バージョン 2** で **`.vscode/cache/refactor-marker/refactor-marker.json`** に保存します。不足するディレクトリは自動作成します。複数ルートのワークスペースでは各フォルダーにグループとキャッシュを分けて保存します。ソースのパスはワークスペース相対で、保存位置は 0 始まり、サイドバーの行番号は 1 始まりです。各グループは追加順の `ranges` 配列を持ち、各範囲に ID、パス、位置、追加日時を記録します。

新しいメタデータが存在しない場合、v0.1.0 の **`.vscode/refactor-marker.json`** を確認します。旧ファイル全体を検証し、単一範囲を 1 要素の配列へ変換して、新しいファイルを一時ファイルからの置き換えで保存します。グループ ID、名前（新規入力の規則に合わない旧名も含む）、色、パス、位置、日時は可能な限り保持します。旧ファイルは変更しません。新ファイルがあればそちらを優先し、毎回重複して取り込みません。旧ファイルを残したまま新メタデータを意図的に削除すると、再読み込み時に再び移行します。

既存データに同じ完全パスのグループが複数ある場合は、読み込みまたは移行時に 1 つへ整理します。作成日時がすべて有効なら、最も古いグループの ID・色・作成日時を保持し、同時刻なら保存データで先に現れるグループを採用します。作成日時の欠落が 1 件でもあれば、保存順で最初のグループの ID・色を保持します。欠落した作成・更新日時だけを、既存の日時や範囲の追加日時、参照できる日時がなければ固定の基準日時から補完します。不正な日時文字列や `null` は補完せずエラーにします。更新日時は補完後の統合対象の最新日時です。範囲は元のグループの出現順、その中の配列順で連結し、同じファイルと開始・終了位置が完全一致するものだけを重複除去します。追加日時での並べ替えや、最古グループの範囲を先頭へ移す処理は行いません。保存済みの名前を勝手にトリムしたり、大文字・小文字をそろえたりはしません。

完全一致ではない重なりを検出した場合は、範囲を勝手に捨てて統合せず、そのフォルダーの読み込み・変更を停止して通知します。日時の補完だけの場合も含め、整理結果は一時ファイルからの置き換え保存が成功してから公開し、保存に失敗した場合は元のメタデータを維持します。新たな **Create Group** や **Add to Existing Group** では、完全一致を含む重複・重なりを追加できません。

不正・読み取り不能なメタデータや移行失敗は通知し、ユーザーデータを上書きしないよう該当フォルダーの変更を停止します。問題のメタデータを修復または削除して、ウィンドウを再読み込みしてください。詳細は出力パネルの **Refactor Marker** に記録します。書き込みには一時ファイルと名前変更を使用し、追従範囲の保存では、変更のある各フォルダーを個別に試行します。Clear All は全フォルダーを事前確認し、エラー時に停止します。複数フォルダーをまたぐトランザクションではありません。メタデータの変更はエクスポートの成否に依存しません。

キャッシュのディレクトリやメタデータにはシンボリックリンクやジャンクションを使用できません。ワークスペースのルートより下のソースパスにこれらが含まれる場合も拒否し、別名によるフォルダー分離や重複検査の回避を防ぎます。ワークスペースのルート自体がリンクの場合は対応しますが、同じ物理フォルダーを複数のルートとして開くとメタデータの上書きを防ぐため拒否します。入れ子のワークスペースルートから競合する範囲を復元した場合は通知し、後から読み込む競合フォルダーの変更を停止します。修復または削除してから再読み込みしてください。

キャッシュをバージョン管理に含めるか無視するかは利用者が決めてください。拡張機能は無視ルールを変更しません。マーカーの作成・変更・削除で、元のソースや無関係な `.vscode` の設定は書き換えません。

## プライバシー

すべてワークスペース内でローカル動作します。外部 API、テレメトリ、クラウドサービス、AI 連携、ソースコードのアップロード、実行時依存パッケージはありません。

## ローカルインストールと開発

**Extensions: Install from VSIX...** から **`refactor-marker-0.2.0.vsix`** を選ぶか、次を実行します。

```sh
code --install-extension ./refactor-marker-0.2.0.vsix
```

開発には Node.js **24 LTS**、または **22.13 以降の 22.x 系**と npm を使用します。

```sh
npm ci
npm run compile
npm run lint
npm run check
npm run watch
npm run package
```

`npm run check` はコンパイルと lint をまとめて実行し、`npm run watch` は変更を監視してコンパイルします。このリポジトリを VS Code で開き、**Run Refactor Marker** 構成で **F5** を押すと Extension Development Host が起動します。別の確認用ワークスペースを開いて動作を確認してください。

パッケージ作成では、リポジトリのルートに **`refactor-marker-0.2.0.vsix`** を生成します。Marketplace への公開は行いません。

## 制限と動作確認

範囲の追従は位置に基づくベストエフォートです。ファイル名変更、コード移動、拡張機能が無効な間の編集、外部からの書き換え、未保存バッファの消失では範囲の作り直しが必要になる場合があります。範囲の先頭または末尾をまたぐ空でないテキストへの置換では、影響した範囲だけを無効化します。範囲全体と周囲をまとめた置換も対象です。範囲と完全に一致する置換では保持します。範囲の全削除や、マーカー同士が同じ行にまとまる編集でも、該当範囲を警告付きで無効化します。他の範囲や子グループは残ります。元に戻す操作で、削除済みの範囲メタデータは復元されません。複数ウィンドウや手動 JSON 編集の競合を統合する仕組みはありません。

F5 で起動した拡張機能開発用ウィンドウに確認用ワークスペースを開き、次を手動で確認してください。表は確認手順と期待結果であり、実施済みの記録ではありません。

| 確認する操作 | 期待する結果 |
| --- | --- |
| 範囲を選んで **Create Group** で `order` を作り、別の非重複範囲で `order` をもう一度指定します。階層名 `order/validation` でも同様に 2 回作成します。 | 色選択は各名前の最初の作成時だけ表示され、`order` と `order/validation` はそれぞれ 1 グループ・2 範囲になります。範囲は追加順で、既存の色は変わりません。大文字の `Order` は `order` と別のグループになります。 |
| 別ファイルで範囲を選び、サイドバー上部の **既存グループに追加（Add to Existing Group）** ボタンから追加先を選びます。 | 選んだグループの末尾へその範囲が追加されます。キャンセルすると変わりません。未選択時や重複範囲では案内が表示されます。 |
| **Orange** のグループを作り、ダークテーマとライトテーマを切り替えます。他の 6 色も順に選びます。 | サイドバーのアイコンと選択一覧で Orange として認識できる橙色が表示され、他 6 色も正常に表示されます。エディターでは約 30% の背景色と読みやすい構文色が表示されます。 |
| `Order/Validation` と深い子グループを展開し、複数ファイルの具体的な範囲をクリックします。 | 内部 UUID が表示されず、グループ・ファイル・行番号から構造が分かります。クリックした範囲へ移動し、無効な範囲ではエラーを表示します。 |
| ソースを保存して VS Code を閉じ、同じワークスペースを開き直します。 | グループの色、複数ファイルの範囲、追加順が復元され、各範囲へ移動できます。 |

下書きの出力では追加順、ファイルのコメント、子関数の入れ子を確認してください。上書きや全削除は、確認用データでキャンセルを含めて試してください。
